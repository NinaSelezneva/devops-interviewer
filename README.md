# devops-interviewer

Тренажёр для подготовки к собеседованию на позицию **DevOps-инженера уровня Middle и Senior**: 302 вопроса по 18 темам с подробными эталонными ответами, теорией по каждой теме, тренировкой карточками с интервальным повторением и пробным собеседованием с таймером.

Какие вопросы задают и откуда они взяты, описано в [docs/research.md](docs/research.md).

## Быстрый старт

Сборка не нужна: откройте `web/index.html` в браузере.

Онлайн-версия: https://ninaselezneva.github.io/devops-interviewer/ (деплоится автоматически при пуше в `main` через `.github/workflows/pages.yml`).

Или через локальный сервер:

```bash
npm start          # пересобирает контент и запускает http://localhost:8080
```

## Возможности

- **Обзор**: прогресс по каждой теме и общая статистика.
- **Тема**: краткая теория и шпаргалка, список вопросов с фильтрами по уровню, типу и статусу.
- **Теория**: подробные главы-учебник, которые читаются по порядку. В карточке вопроса под эталоном есть блок «📖 Разобраться подробнее»: связанная глава раскрывается прямо в карточке, не прерывая тренировку. В конце главы — её вопросы и кнопка «Потренировать вопросы главы». Написана для 13 тем: Linux, сети, Docker, Kubernetes, CI/CD и GitOps, Terraform, облака, мониторинг, безопасность, Git, базы данных, Kafka и очереди, SRE и System Design — 134 главы, на них ссылаются все вопросы этих тем.
- **Тренировка карточками**: вопрос → свой ответ → эталон → самооценка. Используется система Лейтнера: вопросы, на которые вы ответили «Не знаю», возвращаются в той же сессии и раньше попадают в повторение. Горячие клавиши: `Пробел` — показать ответ, `1/2/3` — оценка.
- **Выбор уровня** (Middle / Senior / все) в тренировке и пробном собеседовании, выбор запоминается в браузере.
- **Пробное собеседование**: случайные вопросы из выбранных тем с чередованием тем, таймер на ответ, итоговый процент и разбивка по темам, история попыток.
- **Поиск** по тексту вопросов, ответов, тегам и главам теории.
- Анонимная статистика посещений через [GoatCounter](https://ninaselezneva.goatcounter.com) — без cookies и персональных данных; каждый раздел учитывается как отдельная страница, поисковые запросы не передаются.
- Тёмная и светлая тема, экспорт и импорт прогресса в JSON (прогресс хранится в `localStorage` браузера).

## Структура

```
content/          # вопросы и краткая теория в Markdown — источник правды
  01-linux.md ... 18-messaging.md
theory/           # подробная теория по главам, на неё ссылаются вопросы
  01-linux.md ... 18-messaging.md
scripts/build.mjs # сборщик: content/*.md → web/data.js (+ валидация)
web/              # статическое приложение без зависимостей
  index.html  app.js  styles.css  data.js (генерируется)
docs/research.md  # анализ вопросов и источники
```

## Как добавить вопрос

Допишите в нужный файл `content/*.md`:

```markdown
## Q: Текст вопроса?
level: senior          # middle | senior | lead
type: scenario         # theory | practice | scenario | design | behavioral
freq: 3                # 1..3 — как часто встречается на собеседованиях
tags: kubernetes, сеть
theory: memory, network/tcp   # необязательно: главы подробной теории

Эталонный ответ в Markdown: списки, таблицы, блоки кода, цитаты-подсказки (>).
```

Для практического задания (сломанный конфиг, задача на код) условие пишется перед строкой `???`: оно показывается вместе с вопросом, а всё после `???` открывается как ответ.

Затем выполните `npm run build`. Сборщик проверит метаданные и сообщит об ошибках. Новая тема — это новый файл с front matter (`id`, `title`, `icon`, `order`, `summary`); текст до первого `## Q:` становится теорией темы.

## Как добавить подробную теорию

Файл `theory/NN-<тема>.md` с полем `topic` (id темы из `content/`). Текст до первой главы — вступление, дальше главы:

```markdown
---
topic: linux
---

Вступление: как читать этот раздел.

## Процессы: создание, состояния, зомби и сироты
id: processes

> **Суть:** одна-две фразы, которые нужно запомнить.

Подробный текст главы. Ссылка на другую главу: [Память](#/theory/linux/memory).
```

В вопросе ссылка на главу своей темы пишется как `theory: processes`, на главу другой темы — `theory: network/tcp`. Сборщик проверяет, что все ссылки (из вопросов и внутри текста глав и ответов) ведут на существующие главы, и выводит, сколько вопросов темы уже связаны с теорией.

ID вопроса вычисляется из его текста, поэтому если переформулировать вопрос, прогресс по нему сбросится. Чтобы этого избежать, задайте стабильный `id:` в метаданных вопроса.
